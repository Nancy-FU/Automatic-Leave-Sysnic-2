# 请假自动化 (Automatic Leave Sync)

用 [Claude Code](https://claude.com/claude-code) 把公司邮箱里的请假 / WFH / OOO 邮件，自动整理进 Google Calendar 和年假记录表——不用再手动读邮件、算工作日、填表格。

> 本仓库是私有工作仓库的**公开镜像**：文档结构与规则原样同步，但员工姓名 / 邮箱 / 日历 ID / 表格 ID 等公司内部信息已替换为占位符（`Employee NN`、`<XXX_ID>`），可复用 (Can be reuse) 到其他团队的请假自动化场景。

---

## 这个项目解决什么问题

以前的自动化（Google Apps Script + 浏览器脚本，见 `archive/`）让 AI 每次临场自由判断邮件内容，没有确定性校验兜底，结果：
- 把"回复/审批邮件的人"误记成"请假人"
- 日期年份解析错（把 2026 记成 2027/2030）
- 同一次请假被重复记录、假别标错

这个项目用**明确规则**（见 `PRD.md` §5 防呆机制）约束 AI 判断，而不是放任自由发挥，并把"日历自动化"和"表格登记"拆成两条风险等级不同的流水线。

## 两个阶段

| 阶段 | 状态 | 做什么 |
|---|---|---|
| **Phase 1 / 1b** | ✅ 已上线，稳定运行 | 邮件 → 日历自动同步。定时任务 `vsys-leave-sync` 工作日 9:00 / 15:00 无人值守运行：识别请假/WFH/OOO 邮件，按规则解析人 / 日期 / 假别，查重后写入对应日历。 |
| **Phase 2a** | ✅ 闭环已跑通 | 年假记录表自动登记。因表格没有写 API，只能靠浏览器模拟操作，所以拆成「定时只读比对 + 用户在场手动同步」两步：`vsys-phase2-monthly-diff` 每月第一个星期一只读生成"待登记清单"，用户确认后才实际写入表格。 |
| Phase 2b | 未开始 | 每季度给每人发邮件提醒剩余年假天数。 |

## 核心设计原则

1. **邮件 = 最终确认版本，日历/表格只是派生视图**——两者冲突时以邮件为准（`PRD.md` §5）。
2. **审批人 ≠ 请假人**——请假人一律以邮件串中最早的原始请假邮件寄件人为准，这是历史上踩坑最多的一条。
3. **无人值守的动作必须结构性只读或可回滚**——能自动写日历（有查重、有规则），但表格写入必须有人在场核对，比对任务本身连写工具都不加载。
4. **规则变了，要同步检查"正在跑的那个东西"**——文档改了规则，定时任务的 prompt 也要跟着改，否则线上行为和文档脱节（见 `CHANGELOG.md` 教训 4）。
5. **隐私最小化**——日历事件描述栏只记"谁批准的"，不记请假原因或审批人回复原话。

## 技术栈

- **运行时**：Claude Code (Desktop) scheduled tasks，本地定时任务（受限于"仅 App 开启时运行"，无云端 24h 能力，属已知取舍）。
- **数据源**：Gmail（Inbox + Sent）连接器，只读搜索。
- **写入端**：Google Calendar 连接器（Phase 1，直接 API 写入）；Google Sheets 无写 API，Phase 2 改用浏览器自动化模拟人工操作。
- **唯一姓名/路由真相来源**：`roster.json`（本仓库未包含，因含真实员工信息）。

## 如果你想复用这套思路

这套项目最值得复用的不是代码，而是**踩过的坑总结成的规则**（`PRD.md` §5、`CHANGELOG.md` "沉淀下来的教训"）：审批人误记请假人、Tab 键在表格里不跳格、清空重做前先核对完整性、改规则要同步改任务 prompt……这些教训跨团队通用，建议先读这两份文档再照着搭自己的版本。
